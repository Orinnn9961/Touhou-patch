# 第六阶段：帧输入层与局域网骨架

本阶段把 P1/P2 的每帧输入收敛为统一记录，并实现可独立验证的 UDP 会话、握手、输入包和丢包冗余。默认配置仍为本地输入；网络收到的数据只进入远端帧缓冲，不驱动游戏模拟。

## 运行路径

每次 P2 移动回调按以下顺序执行：

1. 在 P1 上下文仍激活时快照原版输入全局。
2. 通过第五阶段键位层采样 P2 本地输入。
3. 分配从 1 开始的逻辑帧号，生成 `FrameInput`。
4. 把记录写入 128 帧固定容量缓冲。
5. 网络会话已握手时，发送当前帧及最近的冗余帧。
6. P2 继续使用该记录中的本地 P2 输入调用原版移动函数。

```text
P1 原版输入 ----+
                +--> FrameInput(frame, p1Mask, p2Mask) --> 本地环形缓冲
P2 键盘输入 ----+                                  +--> UDP 输入包
                                                   +--> P2 原版移动
```

当前没有替换 P1 完整更新，也没有把网络帧写回 P1/P2。这样可以先验证帧边界和传输格式，不会在射击、资源与 RNG 尚未确定时让远端输入改变游戏状态。

## 帧输入与缓冲

`FrameInput` 包含：

| 字段 | 类型 | 含义 |
|---|---|---|
| `frame` | `uint32_t` | 非零逻辑帧号，溢出时跳过 0 |
| `player1Mask` | `uint32_t` | P1 当前低 8 位游戏输入 |
| `player2Mask` | `uint32_t` | P2 当前低 8 位游戏输入 |

`FrameInputBuffer` 使用 `frame % 128` 定位槽位。写入较新冲突帧时覆盖旧帧；读取必须同时匹配槽位中保存的完整帧号，因此不会把过期输入误认为当前输入。该结构同时用于本地历史、已发送历史和远端接收帧。

## UDP 协议

协议版本为 1，所有包固定 32 字节并显式使用小端编码：

| 偏移 | 大小 | 内容 |
|---:|---:|---|
| 0 | 4 | Magic `COP6` |
| 4 | 2 | 协议版本 |
| 6 | 1 | `Hello` / `HelloAck` / `Input` |
| 7 | 1 | 角色/标志 |
| 8 | 4 | 会话 ID |
| 12 | 4 | 逻辑帧；握手包中为输入延迟 |
| 16 | 4 | P1 输入；握手包中为本机玩家号 |
| 20 | 4 | P2 输入；握手包中为冗余帧数 |
| 24 | 4 | 已收到的最新远端帧 |
| 28 | 4 | 前 28 字节 FNV-1a 校验值 |

主机绑定 UDP 端口并接受相同会话 ID 的第一个 `Hello`；客户端向指定 IPv4 地址发送 `Hello`，收到 `HelloAck` 后完成握手。输入发送会重复最近 `input_redundancy` 帧，重复帧由帧号覆盖，不会增加缓冲状态。

会话 ID 和校验值只用于误包过滤与损坏检测，不提供身份认证或加密。本阶段仅面向可信本地网络。

## 配置

```ini
[phase6]
enabled=1
network_mode=off
listen_port=28765
peer_address=127.0.0.1
peer_port=28765
session_id=12012
input_delay=3
input_redundancy=8
```

`network_mode` 支持：

- `off`：正式默认值，只记录本地帧。
- `host`：绑定 `listen_port`，等待客户端握手并交换输入。
- `client`：绑定临时或配置端口，连接 `peer_address:peer_port`。

`input_delay` 当前进入握手元数据但尚不延迟模拟；`input_redundancy` 已用于实际重复发送，范围为 1..16。日志中的 `network_apply=0` 表示远端输入不会写入游戏状态。

## 自动验证

- `frame_input_timeline`：帧号、零值跳过、环形覆盖、更新、删除与清空。
- `network_protocol`：编码/解码、字段往返、校验损坏、非法会话和非法输入拒绝。
- `lan_session_loopback`：同机动态 UDP 端口上的主客机握手、输入发送、接收和确认帧。
- 原有上下文、资源、P2 输入及六套 SHT 测试继续执行。

## 当前边界

- 网络线程尚未引入；非阻塞 socket 在游戏更新回调中最多读取 32 个包。
- 没有暂停等待、预测、回滚、超时断线、状态哈希或重连。
- 没有把远端输入应用给 P1/P2；本地模式不存在网络行为回归。
- 下一阶段先用双人移动实现两份进程的确定性输入应用与位置哈希，再扩展射击和 Option。
