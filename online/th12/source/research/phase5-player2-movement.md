# 第五阶段：创建 P2 与独立移动

本阶段创建第二个 `PlayerInf`，只启用移动和渲染。P2 不射击、不放 Bomb、不参与受击、碰撞、道具收集或资源结算。

## 验收状态

第五阶段已于 2026-08-15 完成验收：Release `/W4 /WX` 构建通过，CTest 10/10 通过，代理加载与启动器离线校验通过。人工游戏测试确认双机体显示、WASD 正确方向、Space 低速、独立移动、边界限制、移动动画、禁用射击/Bomb/道具/碰撞，以及返回标题和重新进入均正常。运行日志确认低速实际状态为 `active=1`，并确认 P2 在资源银行释放前完成销毁。

## 原版移动入口

TH12 日版 `1.00b` 的完整玩家更新位于 `0x00436BA0`，包含状态机、射击、Bomb、碰撞和资源逻辑。本阶段不调用该函数。

独立移动函数位于 `0x004364F0`，调用约定为 `EDI=PlayerInf*`、无栈参数。它完整处理：

- 从 `0x004D49D0` 读取八方向输入。
- 根据 `PlayerInf + 0xA2C` 的 SHT 移动参数选择普通/低速和斜向速度。
- 更新固定点位置 `+0x988/+0x98C` 和浮点位置 `+0x97C/+0x980`。
- 裁剪游戏区域边界。
- 根据水平速度切换左移、右移和回正动画。
- 更新玩家动画、低速状态和已有 Option 动画位置。

V24 在网络模式的队友距离不超过 48 像素时，读取原版
`PlayerInf + 0x8258` 的低速判定点 ANM VM，并仅清除远端队友 VM 的渲染位。
本地玩家的判定点、队友本体、Option、低速状态和实际碰撞参数不变。距离拉开、
判定点 VM 更换、玩家销毁或退出网络模式时恢复原渲染状态。该效果是本机视觉
状态，不纳入确定性哈希。

固定点边界为：

| 方向 | 固定点值 | 游戏坐标 |
|---|---:|---:|
| 左 | `-0x5C00` | -184 |
| 右 | `0x5C00` | 184 |
| 上 | `0x1000` | 32 |
| 下 | `0xD800` | 432 |

## P2 创建

创建顺序位于 `runtime_player2.cpp`：

1. 使用原版分配器 `0x0046C9EA` 分配 `0xC59C` 字节。
2. 调用原版构造函数 `0x004359A0`。
3. 配置 P2 的角色、机体、输入和 `PlayerInf*` 上下文。
4. 临时把 ANM slot 7 指向第四阶段的 P2 archive。
5. 把 P2 独立 SHT 放入原版预加载入口 `0x004CE8A8`。
6. 在 P2 上下文中调用原版初始化 `0x00435AE0`。
7. 恢复 P1 的 slot 7 和四个游戏全局。
8. 把 P2 更新注册项的回调替换为移动专用回调。
9. 显式启用 P2 更新和渲染注册项；保留原版渲染回调 `0x00437670`。

原版初始化会先注册但禁用回调，随后只通过 P1 单例路径启用。P2 必须单独设置注册项 `+0x04` 的 enabled 位，否则对象存在但不会移动或显示。

P2 初始 X 为 32，初始 Y 从原版固定点位置同步为 400，避免完整状态机未运行时停留在屏外入场坐标。固定点比例为 `1/128`，对应原版 `0x4A3D40` 的双精度常量。

## 独立输入与上下文

默认输入：

| 操作 | P1 | P2 |
|---|---|---|
| 移动 | 方向键 | W/A/S/D |
| 低速 | Shift | Space |

P2 输入只生成以下原版输入位：低速 `0x08`、上 `0x10`、下 `0x20`、左 `0x40`、右 `0x80`。不会生成射击 `0x01` 或 Bomb `0x02`。方向位由 `0x004364F0` 的分支和 `0x004A1148` 的九组方向向量共同确认，不能按位值顺序推测。

原版移动函数只有在 `PlayerInf + 0xA48 >= 4` 时才把低速输入写入 `+0xC598`。该计时通常由完整玩家更新推进；P2 的移动专用回调不运行完整更新，因此会在调用移动函数前把这个门控状态推进到 4，使 Space 仍走原版 SHT 低速参数，而不是在补丁中自行计算速度。

每次 P2 移动回调执行以下顺序：

1. 用 `GetAsyncKeyState` 采样 P2 键位。
2. 保存实时 P1 全局。
3. 激活 P2 的角色、机体、输入和 `PlayerInf*`。
4. 补足完整更新缺失的低速启用门控状态。
5. 调用原版移动函数 `0x004364F0`。
6. 保存 P2 更新后的上下文并恢复 P1。

所以 P2 的 WASD/Space 不会覆盖 P1 的方向键、Shift 或玩家单例。

## 配置

```ini
[phase5]
enabled=1
p2_left=65
p2_right=68
p2_up=87
p2_down=83
p2_focus=32
p2_start_x=32
diagnostic_forced_input=0
```

键值为 Windows Virtual-Key 十进制值，五个键必须在 1..254 内且互不相同。`diagnostic_forced_input` 只用于开发验证，正式运行必须保持 `0`。

## 对称销毁

P1 destroy Hook 首先切到 P2 上下文并调用原版析构 `0x00436270`，注销 P2 更新/渲染回调并清理动画。析构期间临时启用原版资源保留位，避免 P2 销毁 slot 7 的 P1 archive 或提前释放第四阶段资源银行。

随后依次执行：

1. 释放 P2 `PlayerInf`。
2. 清除 P2 上下文。
3. 释放 P2 SHT 和独立 ANM。
4. 调用原版 P1 destroy。

## 人工测试清单

1. 确认 `diagnostic_forced_input=0`，通过 `coop-launcher.exe` 进入一局普通游戏。
2. 确认画面出现两个玩家；P2 默认在 P1 右侧，机体由 `phase4.player2_airframe` 指定。
3. 同时用方向键移动 P1、WASD 移动 P2，确认两者方向可以相反且互不拖动。
4. 先按住 Space 再按 W，让第一次 P2 位移以低速发生；确认 P2 明显变慢。
5. 分别把 P2 推到上下左右边界，确认不会离开游戏区域。
6. 左右移动 P2，确认角色倾斜动画正常；松开方向后应回到正面动画，动画贴图不能变成 P1 机体。
7. 返回标题或关闭游戏，确认没有崩溃。

预期 `coop/logs/patch.log` 依次包含：

```text
phase5 P2 movement lifecycle armed
phase5 P2 created; ... update=movement-only; render=original
phase5 P2 movement observed; focus_active=...; ...
phase5 P2 focus movement observed; active=1
phase5 P2 boundary clamp observed; ...
phase5 P2 destroyed before resource-bank release
```

不应出现 `phase5 P2 creation failed`、`destroy deferred` 或 `phase5 initialization failed`。
