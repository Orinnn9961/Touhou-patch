# 东方星莲船双人联机使用说明

正式版版本：`1.0.0`

## 1. 运行要求

两台电脑必须使用相同的游戏目录和以下文件：

- 日文版 TH12 1.00b `th12.exe`；
- `dinput8.dll`；
- `th12_coop.dll`；
- `coop-launcher.exe`；
- 相同版本的 `th12.dat`。

局域网模式使用 UDP。默认端口为 `28765`，Windows 防火墙必须允许
`th12.exe` 使用该端口。两台电脑应先连接同一个路由器或同一个局域网。

## 2. 机体选择规则

本地双人和网络双人使用不同的选择方式。

### 本地双人

- P1 在游戏原版选机界面选择机体；
- P2 在启动器的“P2 机体”列表中选择；
- P1 使用原版方向键、`Shift`、`Z`、`X`；
- P2 使用 `WASD`、`Space`、`J`、`K`。

### 网络双人

- 创建房间的一方是 P1；
- 加入房间的一方是 P2；
- 网络模式下启动器不显示 P2 机体列表；
- 房主在游戏原版选机界面选择的机体会成为 P1；
- 客户端在游戏原版选机界面选择的机体会被解释为 P2；
- 客户端本地模拟会自动采用房主的 P1，不需要再选择一次 P1；
- 双方游戏内都使用原版方向键、`Shift`、`Z`、`X`。

客户端看到的仍然是原版单人选机界面，但该选择在网络模式中代表 P2。

## 3. 创建房间

1. 双击 `coop-launcher.exe`。
2. 选择“创建房间 (P1)”。
3. 设置房间号、UDP 端口、延迟帧和冗余帧。
4. 按需勾选“锁火力”“锁残机”“自动 Bomb”和“无限复活”。四项互相独立，可以任意叠加；
   仅房主能够设置，客户端会在开局时自动采用房主规则。
5. 同一路由器或稳定 Radmin 首次测试使用延迟 `2`、冗余 `8`。低延迟模式会更频繁地短暂等待远端输入；补丁会在等待时主动补发输入束。
6. 点击“启动游戏”。
7. 在游戏中选择难度、模式、路线和 P1 机体。
8. 进入关卡后游戏会停在加载阶段，启动器显示“等待对方加入”。

主机可先进入等待状态，客户端不需要与主机同时启动游戏。
等待期间如果需要取消本局，点击启动器的“关闭游戏”按钮；启动器会先请求
游戏正常退出，若游戏没有响应才会在约 3 秒后强制结束。

房主规则的具体效果：

- “锁火力”：P1 或 P2 miss 后共享 Power 不降低；
- “锁残机”：P1 或 P2 miss 后共享残机不减少，残机为 0 时仍可正常复活；
- “自动 Bomb”：玩家中弹进入决死窗口时，只要共享 Bomb 库存大于 0，就自动释放该玩家机体的 Bomb 并消耗 1 个；库存为 0 或原版规则不允许释放时，继续按普通 miss 处理。
- “无限复活”：miss 时仍正常消耗共享残机；残机归零后继续允许 P1/P2 完整复活，不进入疮痍。

自动 Bomb 成功时不会发生死亡，因此不会触发死亡结算。锁残机与无限复活同时启用
时锁残机优先，残机不会减少；其余效果仍可独立叠加。

## 4. 加入房间

1. 在主机上运行 `ipconfig`，确认当前网卡的 IPv4 地址，例如
   `192.168.1.10`。
2. 客户端双击 `coop-launcher.exe`。
3. 选择“加入房间 (P2)”。
4. 输入主机 IPv4 地址。
5. 填写与主机相同的房间号、端口、延迟和冗余。
6. 点击“启动游戏”。
7. 在游戏中选择与主机相同的难度、模式和路线。
8. 在原版选机界面选择自己要使用的 P2 机体。
9. 进入关卡，等待双方资源加载和 Ready 校验。

双方准备完成后，房主发送统一开始信号，两边从相同 timeline 的第一帧开始。

同一局域网中，客户端会同时使用填写的 IPv4 和网卡广播寻找相同房间号的房主。
因此 DHCP 地址变化或选错本机网卡时仍有机会自动发现。广播不能穿过路由器；
跨网络使用虚拟局域网时仍应填写房主的虚拟网卡 IPv4。

## 5. 大厅状态

启动器在网络游戏运行期间保持打开，并显示以下状态：

- “游戏已启动”：补丁正在初始化；
- “等待对方加入”：本机已经完成选机，等待另一方；
- “双方正在加载资源”：P1/P2 机体已经交换；
- “双方已准备”：本机资源已经加载；
- “等待双方同步开始”：双方资源已就绪，正在等待房主发出统一开始信号；
- “联机已开始”：Start 屏障已经解除；
- “配置不一致”：机体或补丁资源签名不同；
- “资源加载失败”：P1/P2 资源未能正确建立。

玩家在 Start 之前无法提前运行关卡，因此晚进入不会造成帧号领先。

## 6. 必须手工保持一致的设置

当前版本尚未自动读取和交换难度、游戏模式、路线与练习模式状态。双方必须手工
选择完全相同的设置，否则可能在开始后触发状态校验错误。

大厅会自动校验：

- 网络协议版本；
- 房间号、延迟和冗余参数；
- 房主实际 P1 机体；
- 客户端实际 P2 机体；
- 双方补丁 DLL 资源签名；
- 房主的 TH12 主/副随机数种子与调用计数；
- 开始 timeline。

房主会在 Start 屏障生成统一的随机数快照，客户端在第 1 帧前覆盖本机状态。
这保证敌弹轨迹、随机特效以及中弹时刻不会因两台电脑启动时间不同而分叉。
当前版本使用网络协议 v7，不能与 v6 或更旧的 DLL 混用。v7 将最近
32 帧输入合并到一个 UDP 包中，避免 WiFi、Radmin 等链路因大量独立
冗余包产生排队、卡顿以及单帧永久丢失。V22 默认恢复 V20 的手动延迟模式。

操作延迟和掉帧需要区分处理。`input_delay` 是确定性锁步的手动输入延迟，双方
必须设置相同值；V22 默认 `2`，不再自动提高。高 RTT 链路使用 2 帧时可能等待
远端输入，这是网络稳定性与响应速度的直接取舍。`input_redundancy` 建议
局域网使用 `6` 到 `8`，公网使用 `8` 到 `12`。掉帧通常来自等待远端输入、系统 CPU/GPU
占用或诊断日志写盘，而不是游戏逻辑主动跳帧。测试性能时应关闭 `[phase7] trace`；
当前版本的 `[diagnostics] log_level` 仅保留配置兼容性，不能作为日志过滤开关。还应关闭
浏览器、录屏和杀毒实时扫描，并使用
有线网络或稳定的虚拟局域网。若日志出现 `input stall recovered`，应提高 `input_delay`
或改善链路；若出现 `Timed out waiting`，应先检查丢包、防火墙和 VPN 路由，不要通过
降低超时来掩盖问题。

剧情对话和关底对话默认自动跳过，双方不需要按确认键。补丁覆盖原版消息解释器的
EnemyManager 和回调两条调用路径，仅当消息对象的原生“等待确认”标志成立时临时注入
消息推进位 `0x200`，并在解释器返回后立即恢复输入。它不会写入射击位 `0x01`，
非对话帧也完全不触碰输入，因此不会导致自机持续射击，也不会删除原版关卡脚本的
开始、结束和阶段切换副作用。需要恢复原版对话时，可在
`[phase6]` 设置 `auto_skip_dialogue=0`，联机双方必须使用相同设置。

周期状态哈希默认是诊断模式：差异会写入双方 `patch.log`，但不会强制关闭游戏。
开发确定性测试时可在 `[phase6]` 设置 `strict_state_hash=1` 恢复严格中止。

V17 起 UDP 接收和缺帧重发在独立网络线程完成，游戏线程通过事件等待到包，不再
每毫秒轮询 socket。日志每 600 帧记录一次 `network performance`，其中
`avg_wait_ms`/`max_wait_ms` 是远端输入等待，`rtt_ms`/`jitter_ms` 是链路估计，
`recommended_delay` 仅保留为诊断指标，不会修改模拟延迟。日志中的
`fixed input delay applied` 应与配置相同；`queue_drops` 正常应始终为 `0`。

## 7. 暂停和断线

- 任意一方按 `Pause` 会在帧边界同步暂停；
- 再次按下 `Pause` 后同步恢复；
- 短暂丢包时双方会停下等待缺失输入；
- 正式开局后，远端连续 15 秒没有任何有效数据才判定断线；
- 对端仍在线但某一输入帧暂缺时会持续重发，最长等待 30 秒；
- 房主大厅可持续等待；客户端查找房主超过 15 秒会显示握手诊断并退出等待。

## 8. 故障排查

连接失败时检查：

1. 两边是否都使用最新版 `th12_coop.dll`；
2. 房间号、端口、延迟和冗余是否一致；
3. 客户端填写的是否是主机局域网 IPv4；
4. 防火墙是否允许 UDP 端口；
5. WiFi 是否启用了 AP/客户端隔离；
6. 是否误用旧版协议 DLL；
7. 双方是否选择了相同难度、模式和路线。

发生错误后保留两台电脑的：

- `coop/logs/patch.log`；
- `coop/logs/bootstrap.log`；
- `coop/logs/launcher.log`；
- `coop/lobby-status.ini`；
- 错误框完整文字。

日志正常时应依次出现：

```text
phase13 LAN handshake complete; lobby selection enabled
phase14 lobby airframes agreed
phase14 local player resources ready
phase14 room start barrier released
```

## 9. 公网使用限制

当前版本面向同一局域网。公网使用需要主机进行 UDP 端口转发，并让客户端填写
主机公网 IPv4。当前尚未提供 NAT 穿透、中继服务器、房间列表或自动重连。

## 10. 打包与移动目录

运行时不使用开发机绝对路径。`coop-launcher.exe` 从自身所在目录寻找
`th12.exe`、`dinput8.dll` 和 `th12_coop.dll`；补丁从 DLL 所在目录读取
`coop/config.ini`。因此两台电脑可以安装在不同磁盘和不同路径。

发布测试包时只需要包含：

```text
coop-launcher.exe
dinput8.dll
th12_coop.dll
TH12-Coop-User-Guide-zh.md
coop/config.ini
```

不要包含游戏本体、存档、分数文件、`coop/logs`、`coop/lobby-status.ini`、
构建目录或逆向研究文件。测试者应将补丁文件解压到自己合法持有的日文版
TH12 1.00b 游戏目录。暂时避免超过 260 字符的超长路径。
